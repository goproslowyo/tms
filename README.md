# Simple Talos Metadata Service

A tiny HTTP server that hands each [Talos Linux](https://www.talos.dev/) machine its own machine config, chosen by MAC address.

A Talos machine booted with the `talos.config=` kernel argument downloads its config from that URL. Talos fills in `${mac}` with the MAC address of the machine's first network interface, as `aa:bb:cc:dd:ee:ff`. tms looks for a file named after that MAC address and returns it **exactly as stored**, so any Talos version and any config shape works, including multi-document configs.

```text
 Talos node (boot)                         tms                          configs/
 ─────────────────                         ───                          ────────
 kernel arg:
 talos.config=http://10.0.0.5:8088/talos/config?mac=${mac}
        │
        │  GET /talos/config?mac=aa:bb:cc:00:11:22
        └────────────────────────────────▶  normalise MAC
                                            aa:bb:cc:00:11:22 → aabbcc001122
                                            read  ───────────────────────▶ aabbcc001122.yaml
        ◀────────────────────────────────  200, file bytes unchanged
```

## How a request is handled

| Request | Response |
| --- | --- |
| `GET /talos/config?mac=<mac>` with a matching file | `200`, the file's bytes, `Content-Type: application/x-yaml` |
| valid MAC, no matching file | `404 Not Found` |
| missing or malformed `mac` | `400 Bad Request` |
| any other path | `404 Not Found` |
| any method other than `GET` / `HEAD` | `405 Method Not Allowed` |

The `mac` parameter accepts `aa:bb:cc:dd:ee:ff`, `aa-bb-cc-dd-ee-ff` or `aabbccddeeff`, in upper or lower case. It is normalised to 12 lowercase hex digits, and that becomes the file name: `<12 hex digits>.yaml`. Anything else is rejected with a 400, so a request can never reach outside the config directory.

## Configuration

All settings are environment variables:

| Variable | Default | Meaning |
| --- | --- | --- |
| `MDS_LISTEN` | `127.0.0.1:8088` | Address and port to listen on. Use `0.0.0.0:8088` to serve your network or to run in Docker. |
| `MDS_CONFIG_DIR` | `./configs` | Directory holding the `<mac>.yaml` files. |
| `MDS_LOG_LEVEL` | `info` | `debug`, `info`, `warn` or `error`. |

## Quick start

### 1. Make a config for each node

Generate a cluster's configs with `talosctl`:

```shell
talosctl gen config my-cluster https://10.0.0.10:6443 -o _out
# _out/controlplane.yaml  _out/worker.yaml  _out/talosconfig
```

Give each node its own copy, named after its MAC address. Per-node settings such as the hostname go in a patch. Recent Talos releases (as generated by `talosctl` 1.14) keep the hostname in its own `HostnameConfig` document; older releases used `machine.network.hostname` inside the main config. tms serves whichever form you write.

```shell
mkdir -p configs

cat > cp1.patch.yaml <<'EOF'
apiVersion: v1alpha1
kind: HostnameConfig
hostname: cp1
auto: off
EOF

# Control plane node with NIC aa:bb:cc:00:11:22
talosctl machineconfig patch _out/controlplane.yaml --patch @cp1.patch.yaml -o configs/aabbcc001122.yaml

# Worker node with NIC aa:bb:cc:00:11:33 (no per-node changes)
cp _out/worker.yaml configs/aabbcc001133.yaml
```

The result:

```text
configs/
├── aabbcc001122.yaml   # cp1, control plane
└── aabbcc001133.yaml   # worker
```

Check them before booting anything:

```shell
talosctl validate --mode metal --config configs/aabbcc001122.yaml
```

> These files contain your cluster's secrets (CA keys, tokens). Keep the config directory private, and only expose tms on the network your nodes boot from.

### 2. Run tms

**From source** (Go 1.26+):

```shell
cd src
go build -o tms .
MDS_LISTEN=0.0.0.0:8088 MDS_CONFIG_DIR=../configs ./tms
```

**With Docker**:

```shell
make docker-build
make docker-run      # serves ./configs on port 8088
```

or run the image you just built by hand:

```shell
docker run -d --name tms \
  -e MDS_LISTEN=0.0.0.0:8088 \
  -e MDS_CONFIG_DIR=/configs \
  -v "$PWD/configs:/configs:ro" \
  -p 8088:8088 \
  ghcr.io/goproslowyo/tms:latest
```

The container runs as uid 65532, so the config files must be readable by that user (for example mode `0644`).

### 3. Check it answers

```shell
$ curl -i 'http://localhost:8088/talos/config?mac=AA:BB:CC:00:11:22'
HTTP/1.1 200 OK
Content-Type: application/x-yaml
...
version: v1alpha1 # Indicates the schema used to decode the contents.
...

$ curl -i 'http://localhost:8088/talos/config?mac=aa:bb:cc:00:11:99'
HTTP/1.1 404 Not Found
...
Not Found

$ curl -i 'http://localhost:8088/talos/config?mac=../../etc/passwd'
HTTP/1.1 400 Bad Request
...
Bad Request
```

With `MDS_LOG_LEVEL=debug` (as `make docker-run` sets) the log shows each lookup:

```text
level=info msg="Starting Talos Metadata Config Service"
level=info msg="Listening on 0.0.0.0:8088"
level=debug msg="Raw MAC: AA:BB:CC:00:11:22"
level=debug msg="Sanitized MAC aabbcc001122"
level=info msg="Attempting to load from /configs/aabbcc001122.yaml"
```

### 4. Point Talos at it

Add this kernel argument to the Talos boot media. Keep `${mac}` exactly as written, because Talos fills it in at boot:

```text
talos.config=http://10.0.0.5:8088/talos/config?mac=${mac}
```

Ways to add it:

- **ISO / USB:** add `talos.config=...` as an extra kernel argument when building the image at [factory.talos.dev](https://factory.talos.dev), or with the Talos `imager`.
- **iPXE:** append it to the kernel line. Escape the `$` so iPXE leaves `${mac}` for Talos:

  ```text
  kernel https://pxe.factory.talos.dev/.../vmlinuz-amd64 talos.platform=metal talos.config=http://10.0.0.5:8088/talos/config?mac=$${mac}
  ```

If there's no file for a node yet, Talos gets a 404 and keeps retrying with backoff, so you can add the file while it waits. When a node boots, it fetches its file, installs to the disk its config selects (`UnattendedInstallConfig` in current Talos, defaulting to `/dev/sda`), and joins the cluster.

## Make targets

| Target | What it does |
| --- | --- |
| `make docker-build` | Builds `ghcr.io/goproslowyo/tms:<tag>` and tags it `latest`. The tag is the latest git tag, or `dev`. |
| `make docker-run` | Runs that image, serving `./configs` read-only on port 8088 with debug logging. |
| `make docker-deploy` | Pushes the image to ghcr.io. Requires `docker login ghcr.io`. |
| `make docker-clean` | Stops the container and removes the images. |
